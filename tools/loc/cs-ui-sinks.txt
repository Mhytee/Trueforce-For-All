# tools/loc/cs-ui-sinks.txt
#
# What counts as a UI sink in C#: the one list that sweep-cs.ps1 and
# LocCsLiteralBudget in src/TrueforceForAll.Core.Tests/LocalizationTests.cs both
# read, so the PowerShell sweep and the test that enforces the budget can never
# disagree about which writes are UI. The two walkers are separate code (the
# same arrangement as Get-LocInventory and LocXamlWalker for XAML), but the
# rules themselves live here.
#
# A sink is a place where a string becomes something a user reads. A literal
# that reaches one and is not routed through Loc.T/F/N is untranslatable, which
# is what the sweep counts. Everything else a C# string can be (a log line, a
# JSON field, a file path, an access-code reply, a persisted identifier) is not
# a sink and never enters the count.
#
# Directives, one per line; '#' starts a comment line; fields are whitespace
# separated and an <args> field never contains a space.
#
#   prop <Name>              An assignment to this property name is a sink:
#                            both "label.Text = ..." and a "Text = ..." entry
#                            inside an object initializer. '+=' counts too.
#   ctor <Type> <args>       "new <Type>(...)": the listed arguments are UI text.
#                            An optional namespace qualifier is allowed
#                            ("new System.Windows.Documents.Run(...)").
#   call <Name.Method> <args>  A call by that exact dotted name. A name with no
#                            dot matches the method on any receiver, so
#                            "SetValue" covers "btn.SetValue(...)" too.
#   callre <regex> <args>    A call whose method name matches this regex, on any
#                            receiver or none. The regex body carries no
#                            anchors; the reader wraps it.
#   skipcall <Name>          A call whose own literals never reach a user, even
#                            inside a sink expression. The whole call, arguments
#                            and all, is stepped over. A leading '.' means any
#                            receiver.
#   textcall <Name>          The opposite: a call that composes the text it is
#                            handed, so a literal inside it does reach the user.
#                            Every other call and indexer inside a sink
#                            expression is stepped over, and so is every "new
#                            ..." (whatever text it holds has its own sink site
#                            inside it, which is where it gets counted).
#   watch <Receiver>         Every "<Receiver>.<Method>(" in the plugin must be
#                            listed below as a call sink or as a nonsink, so a
#                            new overload cannot quietly become a blind spot.
#   nonsink <Name.Method>    Named under a watch, and deliberately not a sink.
#
# <args> selects the UI-text arguments of a call: a comma-separated list of
# zero-based positions and C# parameter names. A name matches a named argument
# ("okLabel: \"Got it\""), a position matches by order. Selecting an argument
# that is never a literal costs nothing, so an overload set is covered by the
# union of its text positions.

# only place the text exists as a literal: a wheel-write outcome that ends up in a

# the only WPF control the plugin builds with text in the constructor. The
# plugin's own windows are further down, under the indirect sinks.

# ---------------------------------------------------------------- calls
# TrueforceDialog is the plugin's MessageBox. Parameter names are listed beside
# the positions because okLabel and cancelLabel are usually passed by name.
# The label arguments are selected both by position and by name, because the
# same overload is called both ways: "Show(owner, title, body, kind, "Delete",
# "Cancel")" and "Show(owner, title, body, kind, okLabel: "Delete")".
call TrueforceDialog.Show 1,2,4,5,okLabel,cancelLabel
call TrueforceDialog.ShowError 1,friendly
call TrueforceDialog.ShowChoice 1,2,3,4,5
call TrueforceDialog.ShowConfirmWithCheckbox 1,2,3,6,7,okLabel,cancelLabel
# System.Windows.MessageBox has no call site left in the plugin. Both overload
# shapes are covered at once: MessageBox.Show(text) puts the text at 0,
# MessageBox.Show(owner, text, caption) at 1 and 2, and the arguments that are
# neither (an owner, a MessageBoxButton) are never string literals.
call MessageBox.Show 0,1,2
# DependencyObject.SetValue(TextBlock.TextProperty, "Delete"): the value is the
# second argument. Only a UI dependency property is ever set this way here.
call SetValue 1
# The status-label helpers, by shape rather than one by one, so a new one is
# covered the day it is written: SetBackupStatus, SetPatternStatus,
# SetSessionsStatus, SetDevStatus, SetIRacingMaxNmStatus, SetChangeEmailStatus,
# SetDiscordStatus/-Raw, SetPatreonStatus/-Raw. The Func<string> flavors take a
# lambda, whose body is still inside argument 0.
callre Set[A-Za-z]*Status[A-Za-z]* 0

# ---------------------------------------------------------------- indirect sinks
# A helper that takes text and writes it to a label is a sink at its call site,
# which is where the literal lives. Without these lines a label routed through a
# helper is invisible to the sweep, and the count could be lowered by moving a
# string one call deeper instead of giving it a key. The list below was derived
# mechanically (every method with a string parameter whose body assigns that
# parameter to a sink property) and the argument selectors are the union across
# that name's overloads, so a name used in two windows needs one line.
#
# Three families were found the same way and deliberately left out:
#   - ApplyCommunityEmptyText(kind): its string parameter picks a message, it is
#     not the message.
#   - Label(t) and Input(text) in ModerationNoticesWindow: one-word names that
#     would match anything spelled the same anywhere in the plugin.
#   - BuildChrome, ShowChoice and the TrueforceDialog constructors: the text
#     reaches them from the public entry points above, and a second rule on the
#     same call would count every dialog literal twice.

# Added 2026-09-26, after a review measured what the rules above cannot see.
# Three shapes are regions rather than assignments, so each needs a directive:
#
#   labels <Identifier>      every entry of that declared collection is a label
#   textmember <Name>        every literal that member RETURNS is display text.
#                            Return position only: a member that returns display
#                            text may still switch on string case labels, and a
#                            case label is an identifier, not copy.
#   recordprop <Type>.<Prop> an initializer entry on one of our own records,
#                            counted only inside that type's initializer
#
# Chosen from a mechanical enumeration of every string collection and every
# display-returning member in the plugin, not from a list: a parallel key or
# value array (IdleStyleKeys, FieldKeys, IdleFontValues, IdleColorHex,
# DashDriveContentKeys, GaugeFieldKeys) is deliberately absent, and so are the
# OLED wheel-screen short names, which cannot carry a translation at all
# (docs/localization-plan.md, out of scope).
#
# Adding a rule here is the one legitimate reason a budget number goes up. The
# set grows as more shapes are found: re-run with -WriteBudget in that commit.

# Panel pickers and lists.

labels IdleFontLabels
labels IdleColorNames
labels RemoteDashTabNames
labels AmbientLedModeLabels
labels RevLightEffectLabels
labels WheelBuiltinEffects
